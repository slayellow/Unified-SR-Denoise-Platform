## 1 목표 (Goal)
- 과제: v3 IR x4(Bicubic++ `upsample_mode: auto`, PixelShuffle(2)×2) 출력의 주기-4 격자를 만드는 Phase-2 축을 찾고, 격자 없는 Phase-2 레시피를 얻는다.
- 관찰 근거 (2026-09-23): 보드 x4 1/4 가로 72×·대각 46×, 같은 크롭 FP32 77×/64× → HTP·양자화 무관. Phase-1 v3는 5.4×/26.5×(휘도, P1 채점). P2 재채점(§3)도 같은 양상이고, 1/4h·1/4d 모두 첫 체크포인트 ep20에서 가장 크다.
- 주 지표 · 목표치: 실기 프레임 FP32 격자 점수 `1/4h`, `1/4d` (§2). 목표 `1/4h ≤ 10` 그리고 `1/4d ≤ 30` (Phase-1 수준 = Phase-1 값을 10 단위로 올림. P2의 Phase-1 값 6.66 / 23.04로 P1 때와 같은 목표).
- 보조 지표 (제약): val LPIPS가 BL 대비 노이즈 하한 넘게 나빠지지 않을 것. 선명도비(SR/bicubic, 실기) 보고 — 출하 1.52, Phase-1 1.08 (P2). 격자를 흐림으로 없앤 레시피는 채택하지 않는다. 선명도 하한 숫자는 미정(소유자 결정 대기).
- 보고 전용 (판정에 쓰지 않음, 소유자 결정 2026-09-29): 1/2h·1/2v·1/2d, x2·x3 격자.
- 2단계 목표 (2026-10-03, 소유자 방향 'Phase-1을 따라가는 레시피'): Phase-1만큼 깨끗하면서 Phase-1 이상 선명. 합격선(P3, 두 카메라 92·98): G1 격자 — cam92 1/4h ≤ 10·1/4v ≤ 10·1/4d ≤ 30, cam98 1/4v ≤ 20·1/4d ≤ 30 (1/2h는 D4 결정대로 보고만 — 처음 적은 '1/2h ≤ 60'은 D4와 어긋나 뺐다. 사후 변경 기록: EXP-09-1 점수가 나온 뒤(2026-10-03 20:43:49, 09-1 1/2h 75.6) 판정 문서를 쓰기 전(20:46)에 고쳤다. 09-1의 1/2h는 에폭마다 커져(39.7 → 76.8) 노이즈가 아니라 edge 부호 비교의 실제 효과다) (cam98 1/4h는 bicubic이 9.9라 제외, cam98 1/4d는 시드 편차 ±10이라 20~40은 보류); G2 평탄부 노이즈 0.95~1.15; G3 오버슈트 cam92 ≤ 5.0 %·cam98 ≤ 5.8 %; G4 1화소 점 보존 Phase-1 ±0.15 (보고); G5 격자 제외 선명도 ≥ Phase-1(1.088 / 1.096); G6 val LPIPS ≤ 0.377 (비열등 확인만). G1~G6 통과 + 격자 제외 선명도 1.12 이상이면 DLC로 만들어 소유자가 보드에서 Phase-1과 A/B. 통과하는 것이 없으면 Phase-1(채널 평균 접기)을 출하한다.
- 3단계 목표 · 합격선 P4 (2026-10-04, 소유자 승인): 소유자와 팀장이 Phase-1의 에지가 부족하다고 판단했고, 팀장 요구('명암 대비가 뚜렷하고 에지가 선명할 것')의 주된 뜻은 **에지 쪽 대비**다(소유자 확인 2026-10-04). 그래서 Phase-1은 더 이상 선명도 하한이 아니다. 목표는 09-1 수준 이상의 에지 선명도에 06-1·09-1 수준의 격자, 그리고 저대비 질감 손실을 줄이는 것이다. P3 대비 변경점은 다음과 같다.
  - G1 격자: 그대로.
  - G1b 신설, 격자 절대 진폭: 4×4 위상 접기 중앙값 ≤ 0.10 DN (cam92, cam98, FLIR even). P2 비율은 모델이 배경을 매끈하게 만들면 함께 커지는 문제가 있어 진폭 기준을 더한다. 기준값: 06-1 0.092/0.090/0.066, 09-1 0.062/0.062/0.066 통과, 출하 0.218/0.189/0.130 탈락. 홀드아웃 세트의 P2 비율은 보고만 한다.
  - G2 평탄부 노이즈 0.95~1.15: 그대로이고 두 카메라 모두에 적용한다. 과평활을 막는 선이라 09-1(0.937)을 통과시키려고 완화하지 않는다.
  - G3 오버슈트: over_bic(선명도와 상관 0.994)를 over_lr(출처 LR 3×3 범위 ±2 DN 밖 HR 화소 비율)로 바꾼다. 잠정 기준 cam92 ≤ 4.5 %, cam98 ≤ 5.5 %. 참고값(cam92/98): Phase-1 1.81/1.96, 09-1 3.01/3.90, 06-1 4.03/5.07, 출하 8.28/9.12. 화요일 이후에는 소유자가 보드에서 '헤일로 없음'으로 판정한 가장 높은 over_lr로 다시 정한다.
  - G4 1화소 점 보존: 보고만 한다(그대로).
  - G5 격자 제외 선명도(에지 대비 대리 지표): 'Phase-1 이상'에서 목표치 cam92 ≥ 1.15, cam98 ≥ 1.19로 올린다. 09-1의 1.171/1.210에서 약 0.02(시드 하한의 5배)를 뺀 값이다. 이전의 'DLC 생성 조건 1.12'는 이 값으로 대체한다. 보고 지표로 강한 에지의 10-90 % 폭(`results/release_v3/eval/lib/edge_contrast.py` 기본값, 중앙 단면)을 함께 낸다. 참고값(cam92/98): Phase-1 4.74/4.29 px, 09-1 3.81/3.49 px.
  - G6 val LPIPS ≤ 0.377: 그대로.
  - G7 신설, 저대비 질감: FLIR ADAS 최저대비 50크롭의 격자 제외 선명도 ≥ 0.78 (06-1 0.78, 09-1 0.716, Phase-1 0.893). EXP-00-1과 00-2로 잰 시드 하한이 0.01 이하로 확인될 때까지는 보고만 한다 → 2026-10-04 측정 0.004(0.968 vs 0.972)라 게이트로 쓴다.
  - 판정 가중치: best.pth가 ep20 이하이면 epoch_100으로 판정한다. IR 노이즈 val의 LPIPS가 덜 denoise하는 런에서 이른 에폭을 고르기 때문이다(EXP-08-1 선례).
  - 결과 처리: G1·G1b·G2·G3·G5·G6를 모두 통과하면 DLC로 만들어 보드 A/B에 올린다. 통과하는 런이 없으면 Phase-1을 자동 출하하지 않고, 소유자가 10-06 보드 A/B(Phase-1, 06-1, 09-1, GO 런)로 결정한다. Phase-1은 모든 후보에서 보드상 격자가 보일 때만 출하한다.
  - 채점: `results/release_v3/eval/score_p4.py` 한 번으로 G1·G1b·G2·G3·G5·G6·G7과 에지 폭을 모두 낸다. 기존 스크립트의 지표 코드를 그대로 불러 쓴다.
  - P4 재채점 (2026-10-04, `results/release_v3/eval/scores/p4_reference.json`): 기존 표 값이 그대로 재현됐다. 시드 하한(00-1 vs 00-2)은 FLIR 저대비 선명도 0.004 · fold 0.004(cam92)/0.001(cam98)/0.005(FLIR even) DN · over_lr 0.10 %p · 에지 폭 0.01 px이다. 통과 못 한 게이트: Phase-1은 G5, 06-1은 G1 cam92 1/4v 11.9와 G7 0.780(경계), 09-1은 G2 cam92 0.937과 G7 0.716. Phase-1 행의 val LPIPS는 자체 사전학습 val 값이라 IR val이 아니다. Phase-1의 G6 기준은 0.377(IR val)이다.
  - 사후 변경 기록: G1b, G3, G5, G7의 기준값은 06-1·09-1 결과를 본 뒤 정한 값이다(2026-10-04). 사전 등록의 효력은 EXP-10 이후 런에만 있다. Phase-1, 06-1, 09-1은 같은 스크립트로 P4 재채점한다.
- 데이터셋: RAYSENSE IR `Finetunning_Dataset/train/OPENAI_RAYSENSE_SR` 1,844장, val HR 100장 (`/mnt/data_server/etc/jshong/SuperResolution/`).
- 제약: 배포 구조(Bicubic++ dim32, auto 업샘플, W16A16 HTP) 고정. 연산: RTX A6000 GPU 3 한 장(2026-10-02 기준, 나머지는 타 사용 중)에서 7런 순차 — 단독 실행은 에폭당 약 23초, 런당 약 40분, 전체 약 5시간(10-02 실측).
- 가정: 격자는 가중치 성질이므로 FP32 실기 프레임 점수가 보드 점수를 대리한다. 09-23에 1/4h로만 확인했고(FP32 77 vs 보드 72), 1/4d는 FP32 64 vs 보드 46으로 차이가 있다. 보드 검증 때 P2 집합의 보드 출력으로 다시 확인한다.
- 나중에 결정: 원인 축을 찾은 뒤의 교정 방법(손실 변경, 업샘플러 초기화, 격자 억제 손실 등)은 이 연구의 2단계. 09-14 v3.1 후속(링잉 벌점 항, GV 가중치 하향)도 같은 GV 손잡이라 여기에 합친다(소유자 결정 2026-09-29, `results/release_v3/MANIFEST.md` 'v3.1에서 해결할 것' 1번을 대체).

- 상태 (2026-10-02): 09-28 7런은 ep4~5에서 중단했고(소유자 지시, 당시 `runs/` 경로로 실행) 산출물은 삭제했다. 평가 프로토콜을 P2로 바꿨다(§2). 2026-10-02부터 GPU 3 한 장에서 EXP §3 명령 그대로 순차 실행: 00-1 → 05-1 → 01-1 → 00-2 → 04-1 → 02-1 → 03-1 (기준과 폐쇄 검정을 먼저 — 손실 쪽인지가 3런 안에 갈린다). 큐 로그 `checkpoints/experiments/queue.log`
